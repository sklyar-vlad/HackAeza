# HackAeza

## Запуск

Нужны Docker с запущенным Docker Engine и Docker Compose (`docker compose version`).
Node.js, Go и Postman на компьютере для этого способа запуска не нужны.
Все команды ниже выполняются из корня проекта — папки с этим README.

При первом запуске создайте локальный файл настроек:

```bash
cp infra/.env.example infra/.env
```

Соберите и запустите проект:

```bash
docker compose --env-file infra/.env -f infra/compose.yaml up -d --build --wait --wait-timeout 120
```

Первая сборка скачивает зависимости и образы. Дождитесь завершения команды.
После изменения кода запускайте эту же команду снова: она пересоберёт проект.

По умолчанию доступны:

| Адрес | Назначение |
| --- | --- |
| http://localhost:3000 | Основной сайт |
| http://localhost:3000/docs/ | Документация Scalar с отправкой запросов |
| http://localhost:3000/docs/swagger.html | Swagger UI с отправкой запросов |
| http://localhost:8080/ | Документация отдельно от основного сайта |
| http://localhost:8080/swagger.html | Отдельный Swagger UI |
| http://localhost:8081/healthz | Прямая проверка backend |

`FRONTEND_PORT` в `infra/.env` меняет порт сайта, `HTTP_PORT` — порт backend.
Прокси документации автоматически использует выбранный `HTTP_PORT`.
Отдельная документация использует порт `8080`.

## Как работает отправка запросов

`docs/openapi.yaml` описывает методы API: адреса, параметры, JSON и авторизацию.
Scalar и Swagger UI читают этот файл и строят формы для отправки запросов.

Пример пути запроса:

```text
Браузер: http://localhost:3000/docs/
    → GET http://localhost:3000/healthz
    → nginx передаёт запрос в backend:8081/healthz
    → Go возвращает JSON
    → документация показывает статус и тело ответа
```

nginx — веб-сервер, который раздаёт страницы и пересылает запросы к API.
Пути `/api/`, `/healthz`, `/readyz` и `/metrics` направляются в backend.
`/api/v1/docs` открывает Swagger UI, `/api/v1/openapi.yaml` отдаёт контракт.
Такая же маршрутизация настроена на отдельном порту документации `8080`.
Браузер обращается к адресу открытого сайта, поэтому отдельная настройка CORS
для этого запуска не нужна. Адрес `backend` доступен внутри Docker; в браузере
используйте `localhost` или домен сервера.

## Проверка перед выгрузкой

Сначала проверьте состояние контейнеров:

```bash
docker compose --env-file infra/.env -f infra/compose.yaml ps
```

Все три сервиса должны быть запущены и иметь статус `healthy`.
Затем запустите проверку адресов (нужны Bash и curl):

```bash
bash scripts/check-docs.sh
```

Она проверяет загрузку документации, контракта, ответ backend `/healthz`
и передачу GET/POST-запросов на обоих портах. При успехе все строки начинаются
с `OK`, при ошибке скрипт завершается с ненулевым кодом.
Если изменили порт сайта, передайте адрес явно:

```bash
bash scripts/check-docs.sh http://localhost:3001 http://localhost:8080
```

Проверьте отправку в браузере:

1. Откройте http://localhost:3000/docs/ и раздел «Эксплуатация» (Operations).
2. Найдите `GET /healthz`, нажмите `Test Request` / «Отправить запрос».
3. В открывшемся клиенте нажмите `Send`. Ожидаются статус `200` и JSON
   `{"status":"ok"}`. Это фактический ответ сервера; пример из описания метода
   сам по себе ещё не означает, что запрос выполнен.
4. Откройте http://localhost:3000/docs/swagger.html, раздел «Эксплуатация»,
   раскройте `GET /healthz` и нажмите «Выполнить запрос» / `Execute`.
   Если требуется, сначала нажмите «Параметры запроса» / `Try it out`.
   В блоке «Ответ сервера» должны появиться `200` и тот же JSON.
5. Повторите отправку на http://localhost:8080/ и
   http://localhost:8080/swagger.html, чтобы проверить отдельный вход.
6. Для подробной проверки откройте инструменты разработчика (`F12` → `Network`),
   выполните запрос ещё раз и выберите запрос `healthz`. Проверьте URL,
   метод `GET`, статус `200` и вкладку `Response` с JSON.

**Текущее ограничение backend:** реализован только `GET /healthz`.
Методы входа, клиентов, аналитики и остальные бизнес-методы пока описаны
в контракте, но не реализованы. Ответ `404` от них ожидаем; это не ошибка
настройки документации. Успешный `/healthz` проверяет соединение с backend,
но не готовность бизнес-функций проекта.

Когда появится обработчик входа, авторизацию можно проверить так:

1. Отправьте `POST /api/v1/auth/login` с реальными тестовыми логином и паролем.
2. Скопируйте токен из ответа. Пример токена в документации не является рабочим.
3. В Swagger нажмите «Авторизоваться» / `Authorize`, укажите токен в `appBearer`
   **без** префикса `Bearer`, подтвердите и закройте окно. В Scalar выберите
   Bearer-авторизацию `appBearer` в клиенте запроса и также введите токен.
4. Отправьте `GET /api/v1/auth/me`. В `Network` → заголовки запроса должен
   появиться `Authorization: Bearer <токен>`. При рабочем backend и действующем
   токене ожидается `200`, при недействующем токене — `401`.

## Ошибки и остановка

| Симптом | Что проверить |
| --- | --- |
| `port is already allocated` | Порт занят: освободите его либо измените порт сайта/backend в `infra/.env` |
| `502 Bad Gateway` | nginx не может связаться с backend; проверьте состояние и логи контейнеров |
| `404` на бизнес-методе | Проверьте, реализован ли этот метод в backend |
| Вместо JSON пришёл HTML сайта | Запрос попал в frontend; проверьте URL и пересоберите контейнеры |
| Кнопки нет после изменения кода | Пересоберите проект и обновите страницу с `Ctrl+Shift+R` |

Посмотреть логи:

```bash
docker compose --env-file infra/.env -f infra/compose.yaml logs --tail=100 backend swagger frontend
```

Остановить проект:

```bash
docker compose --env-file infra/.env -f infra/compose.yaml down
```
